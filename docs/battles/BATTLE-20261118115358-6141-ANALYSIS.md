## 5.1 已接受局限 / 挂账债务 (6)
- 终态斜率读数跑在 loadavg 1.31–2.22 的非静默机上；另两次更静的跑（0.55 / 0.93）给出同量级 0.11~0.18 µs/千条，结论对负载不敏感，但未做多机/多日方差估计
- 仍有一处 O(n log n)：trimGlobalBudget 的“收集 + 按 seq 排序”只在 live history 超过 HISTORY_MAX_ENTRIES(4096) 即已超 cap 时触发；其余读数为 O(#live loaders)，history(loader,name) O(k≤8)
- head-only-after-trim 角例按旧口径处理：字节仍计入 blobBytes，但离开可回收索引（旧扫描本就不回收 head-only），由 trim 用例 + 三账校验守
- 死 loader 配额仍随槽释放（per-slot 计数），AlignmentMetaStoreBudgetTest 保持绿，未在本轮重新评估配额策略
- revert 变异策略不适用：把计数器退回全表扫描后行为等价、测试仍绿，会把变异误判成 weak；故改用 4 条 logic 变异并全部 killed
- 本轮未做真机复跑；性能结论来自离线探针（Pr3CommitScalingProbe）同一探针同一口径对照
