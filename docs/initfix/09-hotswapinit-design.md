# 09 `@HotswapInit` 设计草案（T4 显式逃生口）

适用：实现 `@HotswapInit` 或修改其门禁时阅读。**本文只定义契约，不含实现状态**（状态见 `docs/status.md`）。

## 0. 问题与定位

`InitFix` 的默认值来源是**从新字节码里提取字段初始化式**（`docs/initfix/01-safety-gate.md` §1 的 T1/T2）。
提取要求"直线、无分支、无局部变量依赖、通过效应检查"，而实践中大量初始化式不满足：

- Kotlin `?.` / `?:` / `let` 展开成分支（§2.1 已登记，`@RemoldReinit` 无效）；
- 读配置、查表、`ThreadLocal`；
- 跨类依赖（`inner.getId()`）。

这些字段被 T3 拒绝后，存量实例的新增字段永久停在类型默认值。`@HotswapInit` 就是让用户**自己提供值**。

**与三个既有机制的边界**（这是最容易被误解的部分）：

| 机制 | 触发时机 | 做什么 | 谁能写字段 |
|:--|:--|:--|:--|
| `@HotswapInit` | 该字段**本轮新声明**时，补丁阶段 | 提供该字段的值（替代切片提取） | `InitFix` 写，走条件 CAS |
| `@RemoldReinit` | 字段进入本轮候选集时 | 扩展候选集 / 改写入协议为无条件覆写 | `InitFix` 写 |
| `@OnReload` | 每次重定义后 | 生命周期回调（静态一次 / 实例逐一无参调用） | **用户代码自己写** |

一句话：`@HotswapInit` **只换值的来源，不换作用域、不换写入协议**。

## 1. 安全门关系（豁免边界）

### 1.1 被豁免的门

命中 `@HotswapInit` 的字段**不做切片提取**，因此下列判定根本不执行：

| 被豁免 | 出处 | 理由 |
|:--|:--|:--|
| 直线提取要求（无分支、无局部变量依赖） | `01-safety-gate.md` §1 T2 | 值由用户方法算出，不需要直线字节码 |
| 效应检查（非确定性、IO、反射、`ThreadLocal`、进程/类加载…） | 同上 §2 | 用户显式声明"这个值就是现在算出来的样子" |
| 参数回溯不可变证明 | 同上 §3 | 没有形参可回溯 |
| 多根构造器共识 / 构造器指纹一致性 | `02-closure-and-ledger.md` | 值不来自构造器 |
| "构造器里已自行赋值 / 别处写过"的后续加工检查 | `03-runtime-driver.md` | 没有切片可被污染 |
| 闭包期成环检测 | 同上 | 由 §1.3 的窄规则替代 |

### 1.2 不豁免的红线

| 红线 | 说明 |
|:--|:--|
| **作用域** | 注解**不能**把已有字段拉进候选集。候选集仍是「本轮新增 ∪ 台账未决 ∪ `@RemoldReinit`」；`@HotswapInit` 只在这三者已包含该字段时生效。要"每次热更都重算"请用 `@OnReload`。 |
| **T0 零值等价** | 零值等价字段仍判 `NOTHING_TO_PATCH`，注解不复活它。理由：默认值对全部存量实例已经正确，强制写是 `@RemoldReinit` 的职责。确实要强制 → 两个注解一起用（T0 被 `@RemoldReinit` 豁免，写入走 `KIND_FORCE`）。 |
| `LayoutGate` / `LocalClassGuard` / `AnonClassAligner` | 类级前置门，与字段初始化无关，**完全不受影响** |
| 不变量 1 `shouldBeInitialized` 守卫 | 先检查，`being_initialized` 直接跳过 |
| 不变量 4 `LinkageError` 熔断 | 见 §4 |
| 不变量 2/3 `PENDING` 弱键、`PatchReport` 解耦 | 生产者返回的引用**不得**进 `PatchReport`；报告只记字段名与原因 |
| **生产者可链接性** | 方法必须存在、`static`、非 `abstract`/`native`。本轮**新增**的方法可链接（`applyPatch` 在 redefine 之后才 `defineHiddenClass`），本轮**删除**的方法 → 拒绝 |
| **成环** | 生产者不得读取**本轮目标字段**（新增字段 ∪ `@RemoldReinit` 字段 ∪ 台账字段）。静态检查：以生产者为种子、沿**同类**调用图求可达集，命中目标字段的 `GETFIELD`/`GETSTATIC` 即拒绝。复用 `HashSemantics` 的同类调用图，不新建分析器 |
| **签名兼容** | 返回描述符必须能被赋值给字段类型：基本类型要求**完全一致**（不做装箱/窄化）；引用类型允许子类，生成的伴生方法插入 `checkcast`，失败按 §4 记为字段失败 |

### 1.3 为什么不豁免"作用域"

三个理由：

1. 作用域扩展已经是 `@RemoldReinit` 的职责，两套 opt-in 交叉会产生四种组合，每种都要单独证明"值从哪来、写不写"；
2. 若 `@HotswapInit` 能拉入已有字段，用户给一个存在多年的字段加注解就会**在下一次无关热更时**突然重算全部实例的值——这是一个静默的行为突变；
3. "每次热更都刷新"已有正解 `@OnReload`，语义更直白（用户自己写回字段，不需要我们决定写入协议）。

## 2. 签名与执行时序

### 2.1 注解位置与方法名

**`@HotswapInit` 标在字段上**，生产者方法名由约定决定：`hotswapInit$<字段名>`。

```java
public class Counter {
    @HotswapInit
    private List<Item> cache = compute();          // 本轮新增，切片被 T3 拒绝

    private static List<Item> hotswapInit$cache(Counter self) {   // 生产者
        return self.source == null ? List.of() : self.source.items();
    }
}
```

- 注解**不携带字符串**，避免重命名后仍指向旧名字；
- 字段重命名后方法名不匹配 → **拒绝并告警**（fail-closed），不会静默调用错方法；
- 生产者可以是 `private`：伴生类经 `Lookup.defineHiddenClass(NESTMATE)` 定义，具备 nestmate 私有访问能力（现有生成的 `init$F` 已在用这个能力）。

### 2.2 两种签名，调用基数不同

| 形态 | 调用次数 | 用途 |
|:--|:--|:--|
| `static T hotswapInit$f()` | **每轮 1 次** | 值与实例无关：配置、常量表、单例 |
| `static T hotswapInit$f(Host self)` | **每实例 1 次** | 值依赖实例自身状态（Kotlin `a?.b ?: c` 的主要形态） |

**为什么必须区分**：无接收者形态若逐实例调用，一个读配置文件的生产者在百万级堆上会被调用一百万次——既是性能灾难，也是副作用灾难。有接收者形态无法合并（每个实例的值可能不同）。

**实现方式**：无接收者形态在 `applyPatch` 里评估一次，结果写入**伴生类的静态槽**，生成的 `init$F` 读该槽；有接收者形态的 `init$F` 直接 `ALOAD 0` + `INVOKESTATIC`。

**只支持 static，不支持实例方法**：实例方法要走虚分派，会重新引入"调用本次被修改的方法"这个 `InitFix` 一直在防的隐患；而且 `static m(Host self)` 已经覆盖了同样的能力，没有虚分派。

### 2.3 时序：不新增阶段

`@HotswapInit` 只是把"值计算片段"的来源从**提取出的 `InsnList`** 换成**一条 `INVOKESTATIC`**（无接收者形态再加一条静态槽读取）。写入协议、任务结构、依赖集合全部不变：

```
transform（分析，不跑用户代码）
  └─ 命中 @HotswapInit → 跳过 extractFieldInits / checkSafe
     └─ 校验签名、成环、可链接性
     └─ 合成 FieldPatchTask(dependencies = ∅)，值片段 = INVOKESTATIC
redefine
afterRedefine → applyPatch（热更线程）
  ├─ isInitialized 守卫
  ├─ 枚举存活实例（后置）
  ├─ 无接收者生产者：评估一次 → 写入伴生类静态槽
  ├─ 逐实例：init$F → 生产者 → 条件 CAS 写入
  └─ 静态字段：评估一次，直接写
```

三条必须写进契约的推论：

1. **`transform` 里绝不调用生产者**。`transform` 在类加载/重定义回调线程上跑，执行任意用户代码有类加载死锁风险；且那时 redefine 尚未提交，生产者的解析结果可能指向旧版本。
2. **生产者跑在热更线程上**。与现有切片一致。因此读 `ThreadLocal` 拿到的是热更线程的副本——这是 `01-safety-gate.md` §2.1 原本拒绝 `ThreadLocal` 的理由，`@HotswapInit` 把它交还给用户，**必须在 Javadoc 里写明**。
3. **只影响存量实例**。redefine 之后新建的实例走新构造器，执行的是用户原本的初始化式，与生产者无关。两者若算出的值不一致，实例群会分成两半——这是逃生口的固有代价，Javadoc 必须写明"生产者应返回与新初始化式相同的值"。

## 3. 多次热更的重复触发

**契约：不会重复调用。**

候选集在 `buildPatch` 里由 diff 计算：`本轮新增字段 ∪ 台账未决字段 ∪ @RemoldReinit 字段`。v1→v2 新增字段 `f` 并补过之后：

- v2→v3（只改方法体、保留注解）：`f` 不在 diff 里、不在台账里、不是 `@RemoldReinit` → **不进候选集** → 生产者**一次都不会被调用**；
- 这是**结构性保证**，不是运行时开关：`@HotswapInit` 只在"字段已进候选集"时被查询，没有独立触发点。

两个边界：

- **删掉再重新加**同一字段 → 该字段再次成为"本轮新增"，生产者会被重新调用一次。语义正确（新实例群的字段确实是新的）；
- 想"每次热更都重算"→ 用 `@OnReload`，而不是期待注解被重复触发。

**验收方式**：生产者在静态计数器上自增，v3 之后断言计数为 0（见 §5 用例 T7）。

## 4. 异常边界

**策略：捕获继续 + 按字段配额，不 fail-fast。**

与生成切片的区别必须讲清楚：生成切片是纯函数，"抛异常"意味着实现 bug，任一异常都该被当作严重问题；**生产者按设计可以抛**（配置缺失、`self` 的某个依赖字段为 null、Kotlin 的 `!!`）。百万实例上 fail-fast 等于把一次热更变成一次宕机。

沿用 `runIndependentInstanceTasks` 的现有结构：

| 情形 | 处理 |
|:--|:--|
| 生产者抛 `Throwable` | 捕获 → `recordTaskFailure` → 计入该字段配额（`MAX_INSTANCE_FAILURES_PER_FIELD = 8`）；配额耗尽后该字段本轮放弃，剩余实例跳过，`PatchReport` 记 `skippedFields` + 原因 |
| `LinkageError` | 不变量 4 熔断：中止**当前类**的补丁。`BootstrapMethodError` 且 cause 非 `LinkageError` → 只隔离该字段 |
| 无接收者形态评估失败 | 该字段整体失败（等价于配额立即耗尽），不影响其它字段 |
| 静态字段生产者失败 | 该字段失败，不影响其它字段 |
| 生产者返回 `null` 给基本类型字段 | 由描述符校验在 `transform` 阶段就拒绝（§1.2），运行时不会出现 |

**关键一条：运行时失败不写 `FieldLedger`。** 台账的语义是"分析期没能出账，别遗忘"，它会被并回下一轮候选集；若把"生产者抛异常"也写进台账，一个永久抛异常的生产者会让每轮热更都重跑一遍。现状 `recordTaskFailure` 本来就不碰台账，实现时必须保持这一点（不要为了"重试"把运行时失败塞进台账）。

**另外**：生产者**不应**被用来做有副作用的事（写全局状态、发网络请求）。每实例调用形态会在补丁循环里执行 N 次。这一点在 Javadoc 里用强措辞写明，并在分析期对无接收者形态记录一条 info 日志（"evaluated once per hotswap"）。

## 5. 测试与对照组设计

全部用例挂在 `:tests:initFixOracle`（纯 JVM，内存 javac），不依赖 DCEVM。

### 5.1 核心验收用例

| # | 用例 | 断言（终局状态） |
|:--|:--|:--|
| T1 | 分支切片被 T3 拒绝的字段，加 `@HotswapInit` 后补上 | 存量实例字段值 == 生产者返回值（不是默认值）；`PatchReport` 中该字段为 ACCEPTED |
| T2 | 无接收者形态 | 生产者的调用计数 == **1**（不是实例数）；全部实例字段值相同 |
| T3 | 有接收者形态 | 每个实例拿到**自己的**值（构造两个实例，字段值不同，断言各自匹配） |
| T4 | 静态字段 | 静态字段值 == 生产者返回值 |
| T5 | 成环：生产者读本轮新增字段 | `transform` 拒绝，原因含 cycle 关键字；`PatchReport` 记 REJECTED；**不生成** `init$F` |
| T6 | 签名不兼容：生产者返回 `long`，字段是 `int` | 拒绝，原因含 descriptor |
| T7 | 重复触发：v1→v2 新增字段 → v3 只改方法体 | v3 之后生产者计数仍为 **1**（v2 那次），没有第二次 |
| T8 | 作用域：给**已有**字段加 `@HotswapInit` | 不进候选集，生产者计数为 **0** |
| T9 | T0 不被复活：`= 0` 的字段加 `@HotswapInit` | `NOTHING_TO_PATCH`，生产者计数为 **0** |
| T10 | `@HotswapInit` + `@RemoldReinit(OVERWRITE)` | 存量实例的已有非默认值被**覆写**成生产者返回值（走 `KIND_FORCE`） |
| T11 | 异常配额：生产者对前 3 个实例抛异常、之后正常 | 前 3 个记失败；其余补上；`PatchReport` 同时含失败与成功记录 |
| T12 | 异常耗尽配额：生产者对全部实例抛异常 | 该字段本轮放弃，`skippedFields` 含该字段，原因可读；**其它字段仍补上**（字段间隔离） |
| T13 | 运行时失败不写台账 | 失败后 `getUnpatchedFields` 不含该字段 |
| T14 | 生产者方法缺失（字段重命名后方法名不匹配） | 拒绝 + warn，不抛异常、不静默跳过 |

### 5.2 防空转对照（按 `AGENTS.md` §6 的两种对照）

| 用例 | 去触发对照 | 换无关输入对照 |
|:--|:--|:--|
| T1 | 去掉 `@HotswapInit` → 同一字段必须回到 REJECTED，实例字段保持默认值 | 把注解挂到**另一个**字段上 → 目标字段仍是默认值 |
| T2 | 删掉"评估一次"的静态槽逻辑（退化成逐实例调用）→ 计数断言必须变红 | — |
| T3 | 生产者改成返回常量 → 两个实例值相同，断言必须变红 | 交换两个实例的生产者输入 → 值必须跟着交换 |
| T5 | 去掉成环检查 → T5 必须变红（否则检查是摆设） | 生产者改读**非目标**字段 → 必须放行 |
| T7 | 在 v3 之前手动清空 diff（模拟"字段仍算新增"）→ 计数变成 2，断言必须变红 | 用 `@RemoldReinit` 替代 `@HotswapInit` 跑同一序列 → 计数应为 0（证明是注解在起作用，不是别的东西） |
| T8 | — | 把注解换到本轮**新增**字段上 → 计数必须变成 1 |
| T10 | 去掉 `@RemoldReinit` → 存量值保持原值（条件 CAS 跳过） | — |
| T12 | 把配额调大 → 该字段仍会被尝试更多次（断言"尝试次数 == 配额 + 1"） | 换成只抛 1 次的字段 → 其余实例必须全部补上 |
| T14 | 恢复正确的方法名 → 必须转绿 | 把方法名改成另一字段的生产者名 → 必须拒绝 |

### 5.3 必须做变异检查的三处

按 `AGENTS.md` §6"新增或放宽安全门例外必须做变异检查"：

1. **成环检查**：注释掉可达集扫描，T5 必须变红；
2. **签名校验**：放宽描述符比较，T6 必须变红；
3. **评估一次**：把静态槽改成每实例重新调用，T2 必须变红。

## 6. 实现面清单（供后续排期，不含状态）

| 关注点 | 落点 |
|:--|:--|
| 注解定义 | `api/src/remold/annotation/HotswapInit.java`（`@Target(FIELD)`、`RUNTIME`） |
| 生产者发现与校验 | `InitFix.buildPatch` 的候选集段：在 `scanReinitFields` 之后加 `scanHotswapInitProducers` |
| 成环检查 | 复用 `HashSemantics` 的同类调用图（`reachableFrom`），不新建分析器 |
| 值片段合成 | 新增"值来源"抽象：`SliceValue`（现状）与 `ProducerValue`（`INVOKESTATIC` [+ 静态槽读取]） |
| 无接收者形态的静态槽 | 伴生类新增一个 `static` 字段 + 一个静态 setter，`applyPatch` 在循环前写入 |
| 报告 | `PatchReport` 增加"值来源 = producer"标记，便于事后区分"补的是提取值还是用户值" |

**不做什么**：不做跨类生产者分析、不做生产者参数的自动注入、不做"生产者返回失败时回退到切片"（回退会让"为什么这个实例是 0"变得不可解释）。
