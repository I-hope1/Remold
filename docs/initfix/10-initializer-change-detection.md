# L0：已有字段初始化表达式变化检测（设计稿）

> **文档类型**：设计规格（只写规格/决策；实现状态以 [`docs/status.md`](../status.md) 为准）

本文只定义设计，不描述实现状态，也不包含任何补丁写入策略。L0 的目标是**让“初始化块/字段初值改了，但存量实例没有重放”从静默变成可见**；它不负责修复该行为，也不改变 InitFix 的写入协议。

## 1. 要解决的问题

`new XXX() {{ property = ...; }}` 的实例初始化块编译进匿名类 `<init>`。若 `property` 是**已有字段**，它不在 `InitFix` 的默认候选集（只含新增字段 / 台账未决字段 / `@RemoldReinit`），于是：

- 存量实例保持旧值；
- 新实例走新 `<init>`，得到新值；
- 旧/新实例分叉，但没有 `[REINIT]`、没有台账、没有 warn。

同样的盲区也存在于普通具名类的构造器/实例初始化块：`InitFix` 只处理**新增字段**，不比较已有字段的初值切片。

L0 只做“检测 + 报告”，不做自动重置。

## 2. 检测方式

### 2.1 输入

对每个本轮会被 redefine 的类（含匿名类）：

- 旧字节码：`bytecodeCache`（当前生效版本）；取不到时退回 `fetchOriginalBytecode`；
- 新字节码：本批 `newBatchBytes`（对齐后、重织入前的源码级字节；重织入不应参与初值比较）。

### 2.2 比较对象

不能比较“整个 `<init>` 的字节码”：构造器里还有 `super()`、捕获字段赋值、其它字段初始化、日志/校验等噪声。比较单位仍是**字段写入表达式切片**：

1. 对新旧 `<init>` 分别跑现有 `extractFieldInits` 的提取逻辑（可复用其切片构建，但不进入补丁生成）；
2. 对每个**新旧两侧都存在**的实例字段 `f`（`name + desc` 相同、非 `ACC_SYNTHETIC`），得到旧切片 `S_old(f)` 与新切片 `S_new(f)`；
3. 归一化后比较：去掉 label/line number/frame，保留 opcode 与操作数（字段/方法/常量/类型）；`GETFIELD`/`GETSTATIC`/调用按“操作数 + 描述符”比较，不解析被调方实现；
4. 仅当两侧都成功提取、且切片指纹不同，记一条“初值表达式变化”。

### 2.3 必须放宽的一处：写入 owner

现有 `extractFieldInits` 只接受 `f.owner.equals(className)`。双括号/B2 的关键形态是：

```java
class Block { int health; }
new Block() {{ health = 90; }}
```

匿名类 `<init>` 里的字段写入以接收者的静态类型作为 owner。**实测**（javac 11 / 17 / 21 / 25）该 owner 是**匿名类自身**（`T$1.health`，`Fieldref` 的 class 为 `T$1`），而不是父类；JVM 解析时会沿父类链找到 `Block.health`。因此“owner 不等于父类”这一点本身不会让写入消失，真正的风险在**同名遮蔽**与其它编译器/写法可能直接以声明类为 owner（例如显式 `((Block) this).health = ...`）。L0 的检测变体必须：

- 接受 owner 是宿主自身或宿主的祖先；
- 用 `ClassHierarchyOracle`/字段解析确认该 `Fieldref` 解析到的就是目标字段（避免同名遮蔽误判）；
- 只用于**检测**，不把这条写入交给 InitFix 的补丁生成；补丁仍只处理“宿主自己声明的新增字段”。

### 2.4 不检测的情况

- 字段是新增/删除/改类型：分别由 InitFix / LayoutGate 的既有路径负责；
- 字段带 `@RemoldReinit`：显式重置路径已有 `[REINIT]` 日志，不重复报告；
- 切片提取失败（分支、局部变量、黑名单调用）：无法证明“变了”，只记 DEBUG，不产生 warn；
- 多根构造器口径不一致：不比较，记 DEBUG（与 InitFix 的 `fingerprintMismatchReason` 同口径）。

## 3. 输出形式：warn 还是台账

| 形式 | 语义 | 是否持久 | 是否影响后续补丁 | 适用性 |
|:--|:--|:--|:--|:--|
| **warn（推荐）** | 本轮一次性提示“已有字段初值变化未重放” | 否 | 否 | L0 只做可见性，不改变写入 |
| **FieldLedger** | “这个字段没补上，下轮重试” | 是 | **会**重新进入候选集，可能触发写入 | 语义不匹配：L0 明确不自动重置 |

结论：L0 使用 **warn**，不写 `FieldLedger`。台账的契约是“该字段本应被补但没补”，把“按设计不重放”的字段塞进去，会让下一轮 `buildPatch` 把它当候选，违背 L0 的非目标。

建议输出：

```text
[INIT-DRIFT] <类名>: 已有字段初始化表达式变化但不会重放: field1, field2
             （默认只补新增字段；要重置请标 @RemoldReinit 或用 @OnReload）
```

同时写入 `PatchReport` 的可选诊断列表（不参与 `FieldDecision`），便于探针/UI 读取；不改变 `patchGenerated`。

## 4. 降噪

- **每类每轮最多一条 warn**，字段名合并；DEBUG 下才逐字段输出切片差异。
- 只对“本轮确实进入 redefine 的类”检测；被布局门/局部类门/黑名单提前移出的类不检测。
- 同一字段在多个构造器里都有写入时，按“根构造器”聚合；多个根构造器指纹不一致时不报告。
- 连续多轮同一字段初值不变不重复报告；只有切片变化才报告。
- 与 `@RemoldReinit` / `@OnReload` 同时存在时，注解路径优先，不报 L0。

## 5. 范围

建议分两档：

1. **第一档（默认）**：匿名类 + 具名类，但仅当类在本轮 batch 中且存在 `<init>`；覆盖双括号与普通构造器初值。
2. **第二档（开关）**：只报匿名类，用于大型工程先降噪；具名类仍可在 DEBUG 下看。

不建议只做匿名类：具名类的 `field = expr` 初值变化与双括号是同一类盲区，只做匿名类会留下不一致的语义。

## 6. 性能

检测只发生在**本轮 changed 类**上，不对全工程类扫描。每个类的工作量：

- 解析旧/新 `ClassNode`（`InitFix` 已需要新侧解析）；
- 对每个 `<init>` 跑一次 `extractFieldInits` 级别的切片提取；
- 对每个共有字段做一次指令序列比较。

`Blocks.java` 这类包含数百个匿名类的大类，成本按“本轮实际变更的匿名类数 × 每个 `<init>` 的指令数”增长，不按工程类总数增长。设计上要求：

- 旧侧切片可按类缓存（以旧字节 hash 为键），避免同一轮/相邻轮重复提取；
- 只对 `ClassDiff.modifiedBodyMethods` 含 `<init>` 或类含双括号匿名类的类做；方法体完全未变的类跳过；
- 先做常量池/字符串预过滤（`<init>` 是否引用目标字段名），再做 Analyzer。

**性能数据尚未实测**，不在这里给数字。落地前应补一个 `Blocks.java` 风格探针：统计 300 个匿名类 batch 的 L0 检测耗时（min/median/max），并给出“关闭 L0”的对照组；在该数据出来之前，L0 不应默认全量开启。

## 7. 非目标

- 不自动重放构造器；
- 不把已有字段加入 InitFix 补丁候选；
- 不改变 `@RemoldReinit` 的语义；
- 不处理父类字段由子类 `<init>` 写入时的自动补丁（只报告）。
