# v0.2.4 Release Notes (draft for commander review)

Status: **released 2026-11-07** (`v0.2.4`).
Previous release: `v0.2.3` (`0036550`).

## Highlights

- **`@RemoldReinit` scope**: new `scope` element with `SELF` / `INCLUDE_SUBCLASSES` (default preserves
  existing behaviour). `SELF` reinitializes only exact declaring-class instances; host `Class` is
  canonicalized so JBR's old-version "shadow" `Class` cannot corrupt identity filtering after a
  structural redefine. A scope on a static field is ignored with a single `[REINIT-SCOPE]` warn.
- **Forge Mixin template hot update**: `plugin-forge` now drives `IMixinTransformer.reload`
  reflectively and cascades a re-weave + `redefineDynamic` to loaded targets (`ForgeMixinHotSwap`).
  Previously a changed `@Mixin` class was defined into the target loader while `MixinInfo` stayed
  stale, so `@Inject` bodies in targets never updated.
- **Mixin `@Inject` self-evolution**: added/renamed `@Inject` handler methods now hot-swap.
  `MixinClassInfoSync` runs **before** `reloadMixin` (the conform check reads that metadata) and
  rolls back members when reload is rejected.
- **Profiler / entity probe robustness**: `ProfilerTransformer.transform` uses per-call local state
  (reentrant, no shared-field clobbering); stale static-field `Class` refs are normalized via
  `ClassIdentity.canonicalize`; `toggleEntityProbe` catches `Throwable` and rolls back from a
  pre-call snapshot (failed enable restores the registration, failed disable re-registers).
- **Verification tooling**: `probeAll` aggregate task (not in `check`) with zero exclusions; new
  seconds-scale probes for multi-mixin targets, `@Inject` evolution, `sourceBytecodeCache` real-path
  matrix, `LayoutGate` reject→recover, `@RemoldReinit` scope, shadow-Class identity.

## Fixes

- `plugin-mixin`: `MixinInfo.reloadMixin` validated new `@Inject` handlers against the previous
  `ClassInfo`, rejecting added/renamed handlers with `Conform error ... please restart client`;
  sync now happens before reload, with `SyncToken` rollback.
- `plugin-forge`: Mixin template changes were not reloaded (targets kept old handlers); new
  `ForgeMixinHotSwap` reloads the template and cascades target re-weaving.
- `core` profiler: shared mutable transformer state caused `NullPointerException: this.classReader is
  null` and intermittent `ClassFormatError` when `ClassWriter.getCommonSuperClass` re-entered the
  transformer; `transform` is now stateless per call.
- `core` profiler/LibTool: static-field `Class` references rewritten by JBR redefinition (shadow
  `Class` with old fields, `getInstances=0`, silent no-op retransform) are canonicalized at API
  boundaries.
- `core` layout: type-change reject summaries no longer claim the reader scan failed; the note is
  limited to `REMOVED_FIELD`.
- `plugin-arc`: `Injector` used the package-private `RemoldAgent.inst` field across the
  app/bootstrap loader boundary (`IllegalAccessError`); it now uses public `RemoldAgent.getInst()`.

## Known limits / manual acceptance

- **Manual acceptance still pending**: `docs/acceptance/01-manual-checklist.md` (template scenarios
  1–8, build/result columns intentionally empty for the user to confirm; real Fabric 1.21.1 client).
- **Forge upstream Mixin 0.8.5/0.8.7 semantics**: cross-mixin same-name `@Unique` fields are merged
  into a single field (Fabric `sponge-mixin` disambiguates to `<sessionId>$<modId>$<name>$0`).
  Remold's re-weave keeps the merged field stable; this is upstream behaviour, not a Remold defect.
- **Forge `ClassInfo` member sync** for newly added Mixin members was not implemented on the Forge
  side in 0.2.4 (Fabric covers it via `MixinClassInfoSync`), so adding an `@Inject` handler method or
  a `@Unique` field to an existing `@Mixin` required a restart on Forge/NeoForge. Addressed after
  0.2.4 by `plugin-forge` `ForgeClassInfoSync` (sync before `IMixinTransformer.reload`, rollback on a
  rejected reload; see `CHANGELOG.md` → Unreleased and `docs/status.md` §0.3 for the real Forge
  1.21.1 red → green evidence). Structural contract changes (targets / interfaces / inner classes /
  priority) still require a restart.
- **NeoForge Mixin compatibility** was not verified end-to-end in 0.2.4. Addressed after 0.2.4 on
  **NeoForge 21.1.265** (MC 1.21.1, ModLauncher 11.0.5, sponge-mixin 0.16.4) with a real dev
  `runServer` probe whose Mixin config is registered by the loader itself via the native
  `META-INF/neoforge.mods.toml` `[[mixins]]` path: red baseline (`Conform error ... isUnique() ...
  method is null`) -> green (added `@Inject` handler and added `@Unique` field both take effect,
  existing members preserved). See `tests/neoforge-mixin-probe/` and `docs/status.md` §0.4.
  **Still unverified**: NeoForge 26.x / FML 10+ (ModLauncher removed, different loader generation)
  and the production installer launch path (JPMS module ownership may differ from the dev run, so a
  `--add-opens` requirement must be re-tested there). Do not treat the 21.1 dev evidence as covering
  those.
- Container probes cover real **servers** (Fabric KnotServer, Forge `runServer`), not a client GUI;
  evidence hashes are per-process (Mixin sessionId) and not cross-run comparable.
- `alignBaselineProbe`/`offsetStabilityProbe` are JBR-sensitive and require
  `-XX:+AllowEnhancedClassRedefinition`. `offsetStabilityProbe` Probe E's strict "cached Field
  accessor auto-updated" assertion holds on JBR **25.0.2** (the intended p05 JDK); on JBR 21 the
  accessor keeps the stale offset and reads the adjacent `s2=200L` slot, which is an
  environment difference, not offset corruption. `probeAll` must be run with JBR 25.0.2
  (`-Pp05.jbr=<jbr-25.0.2>`); Probe D/D2 now poll `compilation.log` for Tier-4 compilation
  (up to 30 rounds) instead of a fixed 100 ms warmup, which removes the batch-load flake.
