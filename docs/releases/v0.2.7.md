# v0.2.7 Release Notes

Status: **released 2026-11-11** (`v0.2.7`, GitHub release published; tag `0852506`).
Previous release: `v0.2.6` (`2159d21`).

## Highlights

- **A Mixin-generated anonymous class may never change its member schema in place.** The generated
  `Target$Anonymous$<uuid>` class carries its captured variables as synthetic fields, so a changed
  capture list changes the field table **and** the `<init>` descriptors. On a JBR-21 DCEVM host that is
  not a local edit: `redefineClasses` makes the VM re-lay-out instances and rewrites unrelated heaps.
  Measured on a real client (`[观测]`): one such redefine wiped
  `LootContextPredicate.combinedCondition` on 230 of 244 instances
  (`[HEAPWATCH-DIFF] null{before=0 after=230 newlyNull=230}`, both channels `agree=1220 conflict=0`),
  and it did so **even when the synthetic class had zero instances on the heap**
  (`live{raw=0 reachable=0}`) — so the trigger is "member schema differs", not "an old instance exists".
  The gate therefore refuses any schema change (`fieldTableChanged`, computed from the live class's
  reflection table including `isStatic`/`isSynthetic`) and reports it as `gateRejected`. Body-only edits
  keep the fast in-place path.
- **The synthetic class and its host target now fail or commit together.** Refusing the synthetic class
  while still redefining the target is a split state: the target would call a `<init>` the VM never got,
  and the next tick throws `NoSuchMethodError`. A new `BytecodeTransformerBridge.Abort` signal carries
  "do not redefine this class in this round" through the bridge chain: `applyTransformerBridges`
  rethrows it, `redefineDynamic` returns failure **without** calling `redefineClasses`, and the batch
  path drops the class. Neither the newly woven bytes nor the un-woven source bytes are ever handed to
  the VM (the first keeps the split state, the second washes out the mixin hooks). The log now says
  `was NOT redefined … metrics: …` instead of blaming the layout gate.
- **Same-session self-healing, and one refusal per candidate.** A refused candidate is remembered by the
  hash of **the bytes that would have been installed** — never by the target class's own source bytes,
  which do not change when a mixin is edited (that mistake locked a session permanently: restoring the
  capture list still read "stays aborted"). Repeating the identical candidate is suppressed without
  double-counting; changing the capture structure is evaluated again and refused again; restoring the
  capture list to match the live class clears the record and the body edit goes through. `BLOCKED` is
  cleared per round, so a session recovers without a restart.
- **Reload structure contracts broken open.** `@Mixin(priority)` (a `final` field inside a `TreeSet`),
  `@Mixin(targets)` (in-place metadata migration across four indexes with snapshot rollback instead of
  detach + re-register, which now trips `MixinTargetAlreadyLoadedException`) and `interfaces` (two-way
  alignment; superclass changes still rejected, interface add/remove allowed on JBR/DCEVM) no longer
  require a restart.
- **New mixins admitted at runtime, from wherever the IDE puts them.** A four-level byte-source chain
  (registered memory → every watch directory → batch cache → host provider) plus a `MixinBytecodeOverlay`
  that also swaps each `MixinConfig`'s start-up-captured service, plus a `pendingUnresolvedMixins` relay
  (TTL + retry budget) for "`mixins.json` saved first, `.class` compiled seconds later". A pure-IDEA
  `out/production/classes` layout now hot-swaps without a second output directory and without a restart.
- **Access levels only ever move up.** `AccessAlign` aligns a re-woven product against the JVM's loaded
  bytes (`public`/`protected` must not narrow, stripped `ACC_FINAL` must stay stripped) behind a
  fail-closed `[ACCESS-GATE]` self-check, and `readOriginalBytes` replays the loader's pre-Mixin
  transforms (`PackageAccessFixer`, `AccessWidener`, `AccessTransformer`). Before this, one hot-swap of
  `MobEntity.isInAttackRange` sent **112 members** back to `protected` and the VM answered
  `VerifyError: Bad access to protected data` → `InternalError`.
- **A Mixin subsystem documentation set.** `docs/mixin/01..08` now mirrors `docs/topology/`: invariants
  and classloader authority, admission and the bytecode overlay, the re-weave pipeline and member
  alignment (including why baseline synthetic methods and `@Unique` fields may only be tombstoned, never
  deleted), the three reload structure contracts, the synthetic-class single exit, end-to-end
  walkthroughs, runtime gates and the two-channel heap sentinel, and the decision/evidence ledger.

## Fixes

- Read-through `NullPointerException` between `redefineClasses` and `InitFix`: closed on the internal
  batch path by the two-phase redefine (stage A = new structure + old bodies, then instance patches, then
  stage C = new bodies). `-Dremold.agent.two_phase=false` restores the single-phase behaviour.
- Mixin handler's first anonymous class: `Error loading class: Outer$1 (ClassNotFoundException)` followed
  by `innerClass is null` — the new bytes are offered to Mixin's own provider before `reloadMixin`, and
  the upstream negative `ClassInfo` cache entries are evicted.
- Body-only edit of an already-loaded generated inner class: used to end in a silent
  `[DYNAMIC-REDEFINE] no-op` while the old body kept running; the synthetic class is now redefined in
  place and the trailing target `no-op` line is explained in the log.
- `NoSuchMethodError: <Target>$Anonymous$<hash>.<init>(…)` on a retarget round trip: the tombstone stub
  and field policy keeps baseline synthetic members in place, and `ClassInfo.cache` is re-anchored to
  `MixinInfo.getClassInfo()` after every reload/registration so `transformSingleDescriptor` keeps
  remapping `this$0`.
- `NoClassDefFoundError: LoadedTargetSuppressor` under a plugin/core version skew: the suppressor now
  crosses the core boundary as plain JDK `Function`/`Consumer` method references.
- Same-shape anonymous-class ambiguity: decided by body-structure similarity, then by a whole-group
  zero-live-instance fallback; the orphan warning names the holder fields (proven by assignment flow, or
  listed as supertype/interface candidates) and the `@RemoldReinit` escape hatch.
- A field whose initializer allocates a Mixin-generated anonymous class was refused
  (`Nest scan incomplete` / `cannot determine protected status of constructor`); synthetic bytes can now
  be registered in `BytecodeSources`, and the diagnostic names the weaving-generated class.
- A mixin name removed from `*.mixins.json` could be silently re-registered when its class file was
  rewritten; the removal now holds until the name is re-added (Forge/NeoForge included, via
  `ModLauncherClassTrackerSpoof` inside the `prepare()` window).
- Batch stall watchdog: previously covered only the debounce batch; now arms through a scoped
  `enter`/`exit` API covering the manual `triggerHotswap()` entry and `retransformLoaded` as well.
- Gradle plugin: agent JVM arguments were injected only into the loader `client` container, so
  `./gradlew runServer` and the gametest runs started without `-javaagent`; all run containers now get
  the same arguments, and auto-deploy wires `runServer`.
- Release tooling: JitPack publications published the bare version while the packaged shims and both
  templates request `…:v<version>`; publications now use the `v`-prefixed version and the real account
  casing (`com.github.I-Hope1.Remold`).

## Known limits / manual acceptance

- **`<Target>$Anonymous$<hash>` still cannot change its capture list in place.** Restore the capture
  list, keep it stable (`@RemoldReinit`, or move the state into a lambda), or restart. The value-type
  histogram of the 230 wiped fields is `[观测]` (230 named record values vs 14 surviving hidden-class
  lambda values); the underlying `ModifyInstances` mechanism and the classloader/branch attribution stay
  `[推断]`.
- **Fact ③ is closed as "not pursued", not as solved.** In `db74eec` a 3-arg `<init>` existed and the VM
  still threw `NoSuchMethodError`; no further work is planned on it.
- **P2 is an unvalidated `[假设]`.** Naming a new synthetic class by `schemaHash` (load it with
  `defineClass`, then only body-redefine the host) is pre-registered with the criterion "new class loaded
  + host body-only redefine → `newlyNull=0`"; not implemented, not measured.
- **F6 four-way split (append / shrink / type-change / unchanged) is still partial.** The `52830a0` logs
  only support `executed=12/12`, `skipped: not observed` (the skip line was DEBUG-gated), `rejected=0`;
  the new `loaded=/fresh=/flags` lines allow the split on the next real-machine run.
- **The captured `LivingEntity` byte pair is manual-only.** `MixinMemberAlignTest`'s captured regression
  is a hand-run entry point (`manualCapturedLivingEntityBaselineRestore`) because those two ~140 KB
  client classes are intentionally not in the repository and `verifyTestCount` hard-fails on skips.
- **`AnonClassAligner`'s Tier 4 layout gate still only "does not pair"; the host keeps redefining.** The
  mixin synthetic path is stricter on purpose (the host aborts with it). Do not extrapolate one to the
  other.
- Real client GUI acceptance of the toast/batch report remains manual; container probes cover dedicated
  servers only.
