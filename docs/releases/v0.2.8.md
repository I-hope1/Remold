# v0.2.8 Release Notes

Status: **prepared 2026-11-12** (`v0.2.8`; version bumped, gates green, awaiting tag/publish).
Previous release: `v0.2.7` (`0852506`).

## Summary (plain language)

What a regular mod developer will notice:

- **Fewer "read 0/null then crash" moments during hot reload.** When a hot-swapped class gains a new
  field or changes a field type, other threads used to be able to read the field's default value for a
  moment. That window is now closed for the single-class dynamic path as well — the path Mixin uses when
  a target class gains a new `@Unique` field that an `@Inject` handler reads on the next tick.
- **Incompatible edits are refused up front, with a reason.** Enum reordering, enum constant
  add/remove, and deletion of members that still have outside readers are rejected before the reload,
  with a message naming the members and explaining why the runtime cannot repair them. You no longer
  get a "successful" reload that crashes later.
- **Deleted lambdas stop being time bombs.** Old call sites of a removed lambda now receive the last
  real return value instead of `null`/`0`, so chained calls and unboxing no longer throw.
- **Logs are English-only.** Runtime logs and user-facing messages were translated, so GBK consoles and
  log collectors no longer garble them.
- **The Gradle plugin is less surprising.** The agent jar now carries its version; the plugin compares
  it with the configured `remold.version` and automatically replaces a stale local jar. A new
  `cleanRemoldCache` task clears project-level caches after a version change.
- **Scope of this release:** v0.2.8 is a stabilization release. It ships **two new features** (orphan
  lambda body retention, two-phase dynamic redefine); everything else is safety gates, logging, build
  and release quality. The large feature batch was v0.2.7 (Mixin subsystem).

## New Features

- **Two-phase dynamic redefine (`redefineDynamic`).** The single-class entry point now consumes
  `InitFix.requiresTwoPhase` and runs stage A (new shape + old method bodies) → instance patch → stage C
  **synchronously inside the same call**, so callers still see the final state and the public return
  contract is unchanged. Stage C reuses the already generated `runtimeBytes` (no second transformer
  bridge pass, no second `InitFix.transform`). Method-body-only edits keep the single-redefine fast
  path. Covered by `DynamicTwoPhaseRedefineTest` (2/2, recorded `Instrumentation` asserts the call order
  and bytes; mutation `twoPhase=false` turns it red) and by the real-DCEVM
  `redefineDynamicNoBaselineProbe` (13/0, log `two-phase: A -> patch -> C`, existing instance `b=42`).
- **Orphan lambda body retention (non-void, on by default).** A removed lambda's ghost stub now keeps
  the previous round's method body (frames and exception table included) when a liveness gate proves the
  body only references members that still exist; otherwise it falls back to the default stub and
  reports why. `void` orphans stay no-op by default (`-Dremold.agent.orphan_retain_void=true` opts in).
  Retention logs once on first real execution and survives multiple rounds. Spec:
  `docs/topology/11-orphan-lambda-body-retention.md`; tests `OrphanBodyRetentionTest` 6/6.
- **Gradle plugin: agent version reconciliation + `cleanRemoldCache`.** `remold-agent.jar` now writes
  `Remold-Version`/`Implementation-Version` into its manifest; the plugin refuses to start a stale
  auto-discovered agent, re-resolves by the configured version and overwrites the local copy (naming the
  ignored file), while an explicit `agentJar` is only warned about. `cleanRemoldCache` clears the
  project's resolved agent/plugin copies and generated launch scripts; the cross-project shared download
  cache is kept unless `--global` is passed. It is deliberately not wired into `clean`.

## Safety & Compatibility Changes

- **Enum gates consolidated.** The Mixin member aligner no longer swallows enum reorders (`$VALUES` and
  other JVM/javac synthetics are excluded from "Mixin-generated member" detection, and enum classes get
  no field-table reordering / tombstoning). Enum constant add/remove is diffed
  (`addedEnumConstants`/`removedEnumConstants`) and refused with `ENUM_CONSTANT_SET_CHANGED`, and the
  rejection reason now names the measured blockers: already JIT-compiled readers still holding the old
  constant table until deopt, `$SwitchMap$`/`$SWITCH_TABLE$` holders that cannot gain new cases, and
  existing `EnumMap`/`EnumSet` instances that cannot be resized. Backed by 30 independent-JVM probes
  (`tests/enum-append-probe/`), `docs/topology/10-enum-constant-append-infeasibility.md` and `D-ENUM-1`.
- **Removed-member reader scan no longer fails closed on unrelated JDK references.** `ArrayList.<init>(I)V`
  and friends used to make the whole scan "incomplete"; only provably unrelated references are skipped
  now (constructor owner mismatch; platform-prefix owners for non-platform fields/static/private).
  Virtual instance methods stay fail-closed; rejection logs name the first three reader classes.
- **`@RemoldReinit` contract tightened.** `-Dremold.agent.force_reinit` is now a real escape hatch
  (default `false`), a per-field `[REINIT] @RemoldReinit trigger on <class>` line explains why a field
  was replayed, an inherited-scope gate refuses `INCLUDE_SUBCLASSES` when a registered subclass writes
  the same inherited field (`scope = SELF` is not blocked), and the Javadoc documents the "does not do"
  list and the exact `CONDITIONAL` semantics.
- **Runtime logs are English-only** (17 CJK literals across 6 files translated). A new
  `./gradlew :tests:verifyLogLanguage` guard (wired into `check`) fails on CJK/full-width punctuation in
  main-source string literals.
- **Release-coordinate self-check is now case-sensitive.** `verifyReleaseCoordinates` no longer only
  asserts that POM files exist (case-insensitive filesystems hid spelling drift); it validates
  `<groupId>`/`<artifactId>`/`<version>` as case-sensitive literals for both coordinate families. The
  eight JitPack publications and all templates/docs use the real account casing
  `com.github.I-hope1.Remold` (matching `git remote` `I-hope1`). Verified: 16/16 coordinates resolve
  from `mavenLocal`, and both templates resolve `gradle-plugin:v0.2.8` via `help --offline`.

## Fixes

- **Linux aarch64 native library (`UnsatisfiedLinkError`).** The platform matrix mapped Linux aarch64 to
  the Android NDK artifact (bionic ABI), which cannot load under glibc. `NativeLibraryName` now resolves a
  dedicated glibc-2.17 `libtoolaarch64.so` shipped with the repo; CI validates its ABI instead of
  building it (`NativeLibraryNameTest` locks the matrix).
- **CI native-build noise.** The aarch64 artifact is no longer built on the CI runner (zig's internal
  libc++ build ignored `-w` and produced thousands of annotations); probes that intentionally call
  JDK-removal APIs now carry `@SuppressWarnings`.

## Upgrading

- `remoldVersion` / `remold.version` is `0.2.8` in `gradle.properties`, the `remold.gradle(.kts)`
  shims, both templates, and the Gradle-plugin examples. Both coordinate families are published for this
  version: `io.github.i-hope1.remold:*:0.2.8` and `com.github.I-hope1.Remold:*:v0.2.8`.
- No configuration changes are required. `@HotswapInit` (T4) remains **design-only**; use
  `@RemoldReinit` for field-level overrides.
- The external IDE/JDWP redefine channel still performs a single-phase redefine (the JVM hands the
  already-redefined class to the post-callback and provides no second-redefine trigger). This is the only
  remaining read-through window and is tracked as a known residual in `docs/status.md` risk 9.
