# v0.2.8 Release Notes

Status: **prepared 2026-11-12** (`v0.2.8`; version bumped, gates green, awaiting tag/publish).
Previous release: `v0.2.7` (`0852506`).

## Highlights

- **The read-through window is now closed on the dynamic single-class entry too.** Mixin hot-swap
  commonly adds an `@Unique` field to a loaded target and reads it from an `@Inject` handler on the
  next tick. That path runs through `RemoldAgent.redefineDynamic`, which previously committed the full
  new bytecode in one `redefineClasses` call and patched existing instances afterwards — a concurrent
  tick could read `null`/`0` in between. `redefineDynamic` now consumes `InitFix.requiresTwoPhase` and
  runs stage A (new shape + old method bodies) → patch → stage C **synchronously inside the same
  call**: callers still see the final state when it returns, the public return contract is unchanged,
  and stage C reuses the already generated `runtimeBytes` (no second transformer-bridge pass, no
  second `InitFix.transform`). Stage-C failure is split by severity: VM-level failures poison the class
  and leave it at stage A with a restart notice; other failures attempt a best-effort rollback to the
  baseline bytes. Method-body-only edits keep the single-redefine fast path.
- **Frontline P0 safety gates.** The enum-order gate is no longer pre-empted by the Mixin member
  aligner (`$VALUES` and other JVM/javac synthetics no longer trigger baseline member restoration);
  the removed-member reader scan no longer fails closed on unrelated JDK constant-pool references
  (`ArrayList.<init>(I)V` and friends); `@RemoldReinit`'s `-Dremold.agent.force_reinit` is now a real
  escape hatch instead of dead configuration, with per-field trigger reasons, an inherited-scope gate
  (`INCLUDE_SUBCLASSES` + registered subclass writing the same inherited field is refused by name),
  and a rejection message that lists every non-extractable field instead of only the first one.
- **Runtime logs and user-visible strings are English-only.** 17 CJK string literals across 6 main
  sources were translated; a new `:tests:verifyLogLanguage` guard (wired into `check`) fails on any
  CJK or full-width punctuation in main-source string literals. GBK consoles and log collectors no
  longer garble hot-swap diagnostics.
- **Gradle plugin reliability.** `remold-agent.jar` now carries `Remold-Version` /
  `Implementation-Version` in its manifest; the plugin compares the discovered local agent jar against
  the configured `remold.version` and, on mismatch, re-resolves and overwrites the stale jar (naming
  the ignored file in the log). A new project-scoped `cleanRemoldCache` task clears the project's
  resolved agent/plugin copies and generated launch scripts; the cross-project shared download cache
  is kept unless `--global` / `-Premold.cleanGlobalCache=true` is passed.
- **Enum constant-set changes are refused with a measured blocker list.** `ENUM_CONSTANT_SET_CHANGED`
  now names the three runtime blockers — already JIT-compiled readers still holding the old constant
  table until deopt, `$SwitchMap$`/`$SWITCH_TABLE$` holders that cannot gain new cases, and existing
  `EnumMap`/`EnumSet` instances that cannot be resized — backed by 30 independent-JVM probes
  (`tests/enum-append-probe/`, javac 21 and real javac 8 bytecode) and decision `D-ENUM-1`.
- **Orphan lambda bodies are retained (non-void, default on).** When a lambda is removed, its ghost
  stub used to return the type's default (`null`/`0`/`false`), so callers that chained or unboxed the
  result hit NPE / division by zero / AIOOBE. A non-void orphan now keeps the previous round's method
  body (frames and exception table included) when a liveness gate proves the body only references
  members that still exist; otherwise it falls back to the default stub and reports why. `void`
  orphans stay no-op by default (`-Dremold.agent.orphan_retain_void=true` opts in). Retention is
  marked by the 3-arg `onOrphanInvoked(String, boolean, boolean)` and logs once on first real
  execution; multi-round hot swaps carry the retained body over verbatim.

## Fixes

- **Linux aarch64 native library**: the platform matrix previously mapped Linux aarch64 to the Android
  NDK artifact (bionic ABI), which cannot load under the glibc loader. `NativeLibraryName` now resolves
  a dedicated glibc-2.17 `libtoolaarch64.so`, shipped with the repo like the Windows/macOS artifacts;
  CI validates its ABI (`AArch64`, `libc.so.6` + `libpthread.so.0`, glibc 2.17 baseline, non-bionic).
- **CI native build noise**: the aarch64 artifact is no longer built on the CI runner (zig's internal
  libc++ build ignored `-w` and produced thousands of annotations); it continues to be built by
  `compile.bat` and only validated/uploaded by CI.
- **`@RemoldReinit` contract details**: `force_reinit` semantics, the `[REINIT] @RemoldReinit trigger
  on <class>` log line, inherited-scope refusal for `INCLUDE_SUBCLASSES`, and an expanded
  "Does not do" list (compile-time `static final`, records, final-field JMM boundaries, multi-field
  non-atomicity, per-instance runtime class dispatch).

- **Release-coordinate self-check is now case-sensitive.** `verifyReleaseCoordinates` used to only
  assert that the POM files exist; on case-insensitive filesystems (Windows/macOS) a publication
  groupId spelled `com.github.I-Hope1.Remold` while the templates requested the real account casing
  `com.github.I-hope1.Remold` still looked "present" but failed at `mavenLocal` resolution with
  `inconsistent module metadata / bad group`, which also broke template plugin resolution. The gate now
  checks `<groupId>`/`<artifactId>`/`<version>` as case-sensitive literals for both coordinate
  families, the eight JitPack publications and all templates/docs use the real account casing
  (`com.github.I-hope1.Remold`, matching `git remote` `I-hope1`), and the `I-Hope1` drift in
  `gradle-plugin/README.md` is fixed.

## Upgrading

- `remoldVersion` / `remold.version` is `0.2.8` in `gradle.properties`, the `remold.gradle(.kts)`
  shims, both templates, and the Gradle-plugin examples. Both coordinate families are published for
  this version: `io.github.i-hope1.remold:*:0.2.8` and `com.github.I-hope1.Remold:*:v0.2.8`.
- No configuration changes are required. `@HotswapInit` (T4) remains **design-only** — the T4 escape
  hatch listed in `docs/initfix/09-hotswapinit-design.md` is not implemented; use `@RemoldReinit` for
  field-level overrides.
- The external IDE/JDWP redefine channel still performs a single-phase redefine (the JVM hands the
  already-redefined class to the post-callback and there is no second-redefine trigger); this is the
  only remaining read-through window and is tracked as known residual in `docs/status.md` risk 9.
