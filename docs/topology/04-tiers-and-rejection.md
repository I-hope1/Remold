## 1. 四级置信度梯队判定表

系统按四级置信度体系分层推进，实行 **两趟制**匹配：第一趟仅采纳双向互为唯一候选的配对，消除遍历顺序依赖；第二趟按规则处理歧义候选：

| 梯队       | 判定条件                                                                                | 置信度      | 唯一候选时的动作                 | 多候选平局时的动作                                  |
|:-----------|:----------------------------------------------------------------------------------------|:------------|:---------------------------------|:----------------------------------------------------|
| Tier 1     | **Self Hash 相同 + 宿主方法相同 + 描述符相同**                                          | 极高 (0.99) | 立即采纳锁定                     | 按 `PAIR_COMPARATOR` 数值 minDiff 仲裁              |
| Tier 1.5 *(目标设计)* | **内容相似度 (方法体哈希交集率 >= 70% + 字符串 Jaccard >= 0.8)**                        | 高 (0.80)   | 采纳并记录日志                   | 差值相等无法区分时，降级至 Tier 3（规格定义见下文，落地状态见 status.md §4.1） |
| Tier 2     | **Self Hash 同类跨宿主方法匹配 (同外层类)**                                             | 中高 (0.75) | 仅当全类唯一样本时采纳           | 存在多个候选时禁止采纳，降级至 Tier 3               |
| Tier 3     | **同宿主方法 + 同基类 + 同接口 + 同字段表 + 同声明方法表**                              | 中 (0.65)   | 采纳并记录日志                   | **拓扑相等过滤**（取代 minDiff 仲裁，见下文）       |
| Tier 4     | **同宿主方法 + 同基类 + 同接口 + 状态布局门检查**                                       | 低 (0.35)   | 仅当作用域内为双向唯一孤本时采纳 | **同作用域存在 >= 2 个同基类候选时，直接拒绝**      |
| Tier 3.5 *(结构同形消歧，见 §2.4)* | **同宿主方法 + 同父类/接口 + 方法体结构相似度（屏蔽匿名类编号、排除字面量、严格 margin、双向唯一）** | 中（带 margin 的证据） | 采纳并记录（`bodySimilarityMatches`） | 证据不足时继续走 Tier 4.5 |
| Tier 4.5 *(扫描可见零存活兜底，见 §2.4)* | **歧义组内每个旧候选均无扫描可见存活实例 + 结构签名全等 + `LayoutGate` 兼容** | 低（确定性兜底，非语义证明） | 按 minDiff 配对并显式留痕（`deterministicZeroScanPairs`） | 不介入，交回孤儿化 + 点名告警 |
| *(已废除)* | *历史 Tier 5（按物理类名盲配）已彻底移除，未匹配类一律判为新增类或孤儿类，严禁内存篡夺* | -           | -                                | -                                                   |

## 2. Tier 3 拓扑相等过滤（取代 minDiff 仲裁）

### 2.1 为什么废除 Tier 3 minDiff 仲裁

传统 minDiff 使用物理类名序号之差 `|n.orderIndex - o.orderIndex|` 作为 tie-breaker。在前插新匿名类且旧类方法体被修改的场景下，新插入的类序号恰好等于旧类序号（
`diff = 0`），而真正的旧类位移后 `diff = 1`。minDiff 会系统性地偏向新插入的类，导致老实例的方法表被新类篡夺。

### 2.2 拓扑签名定义（`TopologySignature`）

为在 Tier 3 确定性区分多候选且不依赖物理序号，引入正交的粗粒度拓扑签名 5 元组：

1. `anonChildren`：直接匿名子类个数（按名字层级：直接父类为本类）；
2. `anonDescendants`：更深层的匿名后代总数；
3. `indySites`：`invokedynamic` 调用点数量（Lambda 创建点）；
4. `lambdaMethods`：合成 `lambda$` 方法个数；
5. `childKinds`：直接子类的类型多重集（父类 + 排序接口，类名屏蔽为 `#ANON#`）。

### 2.3 过滤与判定规则

1. 对剩余候选集进行拓扑签名比对；
2. 仅当新类与旧类拓扑签名 **严格相等**且满足 **双向唯一**时予以配对（计入 `topologyMatches`）；
3. 签名未知（子类字节码无法获取）视为不相等；
4. **无法唯一区分时的保守代价**：若候选在拓扑维度同样无信息（如夹具 M：两个候选与旧类均为空拓扑结构）或属于同构候选群（如夹具
   L：2×2 候选对拓扑签名完全相同），系统 **坚决不进行盲猜仲裁**，在非严格模式下退化为新增/孤儿类，在严格模式下直接熔断拒绝宿主组。这是消除静默错配所付出的保守代价。

### 2.4 Tier 3.5 / Tier 4.5：结构同形歧义的两级消解

Tier 3 / Tier 4 之后仍存在“同宿主方法 + 同结构”的匿名类群（例如同一方法内两个同接口同结构的
匿名类，客户端 R2b 形态）时，按下列顺序补充证据；严格模式（`-Dremold.agent.anon_strict=true`）
**不参与**这两级，保持“没有唯一证据就整组拒绝”的既有语义。

1. **Tier 3.5 —— 方法体结构相似度**：屏蔽匿名类编号后比较指令流相似度，字面量不计入；只在
   “最优候选显著优于次优（严格 margin）且双向一致”时采纳（计入 `bodySimilarityMatches`）。
   相似度是**带 margin 的证据**，不是可证明的同构，因此与 Tier 3 的拓扑判定分开计数。
2. **Tier 4.5 —— 扫描可见零存活兜底**：仅在 Tier 3.5 仍无法消歧时进入。条件为
   **歧义组内每一个旧候选在本轮 JVMTI 堆扫描下都没有可见存活实例**，且配对双方的父类/接口/
   字段表/方法签名完全一致、`LayoutGate` 判兼容；满足后按 `PAIR_COMPARATOR` 的 minDiff 顺序
   做确定性配对（计入 `deterministicZeroScanPairs`）。

**Tier 4.5 的日志与证据契约（不得放宽）**：

* 每一对都必须显式打出 `[ANON_ALIGN] deterministic-zero-scan-pair (scan-visible live instances: 0)`，
  不得伪装成结构唯一匹配；文案必须写成“**扫描可见的活实例为 0**”，不得写成“实例已死”“无存活实例”
  或任何等价的安全保证。
* 判据的语义边界：JVMTI 堆扫描只回答“本轮扫描看见了什么”。扫描看不见的实例不被它否证
  （例如宿主字段长期持有、或在扫描之后才创建的对象），因此该判据**不是**语义安全证明，
  该行日志只能作为审计线索。
* 宿主字段可能持有被配对旧类时，日志必须点名持有者字段，并区分证据强度：
  `proven`（字段静态类型精确等于该匿名类，或方法体 `NEW <anon>` → `<init>` →
  `PUTFIELD`/`PUTSTATIC` 直接赋值）与 `candidate`（字段声明为该匿名类的父类型/接口，可能装着
  别的实现）。存在 `proven` 持有者时该行升级为 `warn`。无任何持有者字段时不得凭空点名。
* 同一份 liveness 判据派生的其他放行/诊断文案（如 `[ANON-LAYOUT]` / `[LAYOUT-WAIVE]` 的
  “布局不兼容但扫描未见存活实例”放行、歧义诊断里的 `scanVisibleLive=` / `scanVisibleLiveOld=`）
  必须使用同一“扫描可见”口径，不得把判据表述为实例死亡或安全性结论。

## 3. 多轮基线与比较器契约

在允许 minDiff 仲裁的极高置信层（Tier 1）中，采用确定性比较器：

```java
private static final Comparator<CandidatePair> PAIR_COMPARATOR = (p1, p2) -> {
	int cmp = Integer.compare(p1.diff, p2.diff);
	if (cmp != 0) return cmp;
	cmp = Integer.compare(p1.n.orderIndex, p2.n.orderIndex);
	if (cmp != 0) return cmp;
	cmp = Integer.compare(p1.o.orderIndex, p2.o.orderIndex);
	if (cmp != 0) return cmp;
	cmp = p1.n.name.compareTo(p2.n.name);
	if (cmp != 0) return cmp;
	return p1.o.name.compareTo(p2.o.name);
};
```

## 4. 失败安全熔断机制 (Reject & Rollback)

### 4.1 熔断触发条件

当触发以下条件时，系统 **拒绝本次结构性重定义**并执行回滚：

1. **低置信度同构平局**：在 Tier 4 阶段，同一个宿主作用域内存在 >= 2 个同基类匿名类且无法确定性区分；
2. **嵌套深度超限**：闭包嵌套深度 `depth > 4`（在 strict 模式下触发拒绝）；
3. **后置校验失败**：目标类名发生冲突（非单射），或子类目标前缀未能以父类目标前缀收敛（`validateRenameMap`）；
4. **数量硬上限与超时**：匿名类数量超过 128 或处理时间超过 2000ms（见 [06-runtime-and-perf.md](06-runtime-and-perf.md)
   §3）；
5. **对齐总开关关闭**：`-Dremold.agent.anon_align=false` 时，含匿名类的宿主整体拒绝。

### 4.2 拒绝粒度与响应规范

* **拒绝粒度**：以**“宿主类 + 其下属全部匿名类”**为原子单元整体拒绝移出本批重定义，避免宿主新字节码引用未对齐编号或老实例被无关新类顶替。
* **回滚动作**：
    1. 抛出统一拒绝异常 `AlignmentRejectedException(hostSlash, reason)`；
    2. 调用 `tx.rollback(true)`，清除预登记的 pending 注入项；
    3. 控制台输出显式告警提示：  
       `[HOTSWAP-REJECT] Structural ambiguity detected in Foo. Redefine skipped safely. Please hot-swap again or restart.`
    4. 其它未受影响的宿主类继续正常推进热更新，杜绝单类故障导致整轮热更静默失效。

## 附：Tier 3.5 与 Tier 4.5（本战役新增）

两档都是"结构同形、无法靠字段表唯一证成"时的**带证据消歧**，都只改变"能不能配对"，不改变布局门判据。

### Tier 3.5 · 方法体 token 相似度消歧

结构（父类/接口/字段表）完全同形、但方法体不同的多个旧候选，按**方法体 token 集合的相似度**打分：
唯一最高分才配对，并列即视为歧义（进入严格模式熔断）。实现在 `AnonClassAligner`（`Tier 3.5` 段，
计数 `ambiguousMatches` 之外的 `tier3_5` 采纳数）。`[推断]` "token 相似度能代表行为同源"是启发式前提，
未做真机穷举；因此它**只在结构完全同形**时启用，且从不单独决定布局兼容性。

### Tier 4.5 · 全组零存活确定性配对

严格置后：只有 Tier 3.5 仍无法消歧才进入。判据是**本轮堆扫描对这些旧候选没有可见存活实例（扫描可见为 0）**
+ 配对双方布局完全兼容。放行时打
`[ANON_ALIGN] deterministic-zero-scan-pair (scan-visible live instances: 0): new -> old`。
同一约定与布局门一致：**"扫描没看见"不是"实例已死"的证明**，日志必须写明这一点。

### `findHoldingFields`：三层持有字段点名

拒绝/告警时点名"是谁还持有这个实例"，三层依次尝试：

1. **精确描述符**：字段描述符精确等于旧匿名类；
2. **赋值流**：`NEW … PUTFIELD/PUTSTATIC` 赋值流可证该字段被写入过该类型实例；
3. **父类型/接口候选**：字段类型是旧类的父类型或接口，可能持有它（只能点名，不能证明）。

三层都命中不了时，提示 `@RemoldReinit` 逃生舱（显式声明该字段可在重定义后重放初值）。
