# B1 旁路账的内存与 GC 基线读数

文档类型：实测记录（读数与口径；机制状态以 [`docs/status.md`](../status.md) 为准）

## 1. 这份读数回答什么

PR4-B2 要引入按代 `FieldLedger` 与跨代事实索引，届时需要一组**引入前**的基线才能判断"新增的账是否真的多占内存/多花 GC"。
本文件固定那组基线：在真实 agent + 真实 redefine 下连续热更互依赖类，分两档字节预算，记录
Retained Heap、OldGen 占用与 GC Pause。

探针：`tests/src/VcsGcBaselineProbe.java`，任务 `./gradlew :tests:vcsGcBaselineProbe -Pp05.jbr=<DCEVM JDK>`。

## 2. 口径（先看口径，再看数）

| 项 | 取值 |
|:--|:--|
| 夹具 | 四个互依赖类 `D → C → B → A`，每类带一个自身常量；`D.d()` 返回四条方法调用之和 |
| 每轮操作 | 轮换重编其中**一个**类并把它自身的常量 +1，其余三个类字节不动 |
| 轮数 | 预热 4 轮（不计入）→ 阶段一 30 轮 → 阶段二 30 轮 |
| 阶段一预算 | `remold.vcs.eff_bytes` 缺省（16 MiB） |
| 阶段二预算 | `remold.vcs.eff_bytes=0`（强制淘汰，模拟预算压力） |
| Retained Heap | 每轮结束后两次 `System.gc()` + 40 ms 静置，再读 `MemoryMXBean.getHeapMemoryUsage().getUsed()` |
| OldGen | 同上时刻读名字含 `Old`/`Tenured` 的 `MemoryPoolMXBean` |
| GC Pause | 本轮开始到本轮批处理结束之间 `GarbageCollectorMXBean.getCollectionTime()` 的增量；**采样点在 settle 之前**，因此不含 settle 自身触发的回收 |
| 统计量 | 每阶段 30 个样本的 min / median / max；三档同时报，不挑有利的那个 |

**探针同时断言机制真的在跑**（否则"曲线平"会被误读成"账很便宜"）：

- 每轮断言新常量在整个依赖图上可见（`D.d()` 等于四个常量之和）——下面 131 条断言里绝大多数是这条；
- 每轮断言 `Changeset` 链恰好前进 1 代（`seq_after == seq_before + 1`）；
- 阶段一断言零淘汰，阶段二断言淘汰计数确实增长（否则"第二档预算"名不副实）。

## 3. 读数

环境：JBR 21.0.8（`-XX:+AllowEnhancedClassRedefinition`）、`-Xmx1g`、单机单次串行运行（不与其它构建/探针并行）。

| 阶段 | Retained Heap (MB) min/median/max | OldGen (MB) min/median/max | GC Pause (ms) min/median/max | Eff 保留字节 min/median/max |
|:--|:--|:--|:--|:--|
| 阶段一 · 默认 16 MiB | 15.78 / 15.83 / 15.87 | 15.78 / 15.83 / 15.87 | 0 / 0 / 0 | 2389 / 6346 / 10081 |
| 阶段二 · 强制淘汰 0 B | 15.87 / 15.88 / 15.89 | 15.87 / 15.88 / 15.89 | 0 / 0 / 0 | 10081 / 10081 / 10081 |

结算读数：`effBytesHeld=10081`、`effDropped>0`（阶段二）、`scopes=[1]`（单 scope，符合"四类同一加载器"）。

## 4. 怎么读这组数（已观测 vs 推断）

**已观测**

- 两阶段的 Retained Heap 中位数相差约 `0.05 MB`（15.83 → 15.88），量级与"少存了不到 10 KB 的 Eff 字节 + 多记了淘汰计数"一致；
  本夹具规模下**账本身的内存占用没有被 GC 曲线单独分辨出来**。
- 阶段二 `Eff 保留字节` 三档全等于 10081，即该阶段**零新增保留**（淘汰生效），而热更与提交链仍逐轮推进 1 代 ——
  "字节被淘汰" 与 "记账/提交继续工作" 是两件事，回退能力才是代价（回退此时会判 `NOT_REVERTABLE`）。
- 每轮 GC Pause 增量在毫秒精度上全为 0，说明单轮批处理落在这个分辨率的噪声里。

**推断（附前提，未升级为观测）**

- "账的内存影响可忽略" 只在**本夹具规模**（4 类 / 每类单方法 / 30 轮 / 单 scope）成立；
  真实工程里类数、方法体规模与别名链都大一到两个量级，需要以同一探针换夹具重测后再引用。
- GC Pause 的 0 ms 是**分辨率限制**而非"没有回收"：`getCollectionTime()` 是整毫秒累加值，
  单轮批处理低于 1 ms 时读不出来。要拿到亚毫秒证据需要 `-Xlog:gc*` 时间戳对齐，本文件不含该实验。

## 5. 本组数的边界

- 单机、单 JVM、单次运行；不同 CPU/堆参数下绝对值会移动，**只做同口径前后对比**（B2 引入后按同一探针同一参数重跑）。
- 未覆盖：多 scope（多个 `ClassLoader`）、大方法体、lambda 对齐路径（本夹具无 lambda，且 `PENDING_VCS` 的 lambda 分支未参与）。
- 未覆盖：`-Xlog:gc*` 级别的回收次数/晋升量分解；本文件只有毫秒级暂停增量。

## 6. B2 引入后的对比方法

同一探针、同一参数、同一轮数与预算两档，重跑一次；对比项固定为
`Retained Heap median`、`OldGen median`、`GC Pause max`、`Eff 保留字节 median` 四个数，
并同时报 min/max 以说明分布。**不得**只报中位数、也不得跨口径（换夹具/换堆参数/换轮数）拼接对比。

不与其它构建/探针并行。断言 131/131（每轮新常量在依赖图上可见、链恰好前进 1 代、阶段二淘汰确实生效）。

## 8. 怎么读这组 B2 数（已观测 vs 推断）

**已观测**

- 两档预算下的 Retained Heap / OldGen 三档读数都**低于** §3 的 B1 基线约 `0.09–0.14 MB`
  （阶段一中位 `15.69` vs `15.83`；阶段二中位 `15.74` vs `15.88`）。两组是**同口径的两次独立运行**，
  但**不是同一次运行内的前后配对**：绝对值随机器负载与 JIT 状态移动，这个量级的差值**不能**归因于
  "B2 的账更省内存"。可复述的结论只有一条——B2 没有让该夹具的 Retained Heap 越过 B1 的
  `15.78–15.89 MB` 区间。
- 阶段二 `Eff 保留字节` 三档全等于 `10081`，且 `effDropped=30`：热更与提交链仍逐轮推进 1 代，
  "字节被淘汰"与"记账/提交继续工作"是两件事。
- 每轮 GC Pause 增量在毫秒精度上全为 0（与 §3 相同，属分辨率限制而非"没有回收"）。

**推断（附前提，未升级为观测）**

- 本夹具**不产生重放事实**：四个互依赖类没有新增字段、没有 `L1`/`A` 档重放、没有 `@RemoldReinit`，
  因此 `GenerationalFieldLedger` 在这个探针里**只被调用、不被填充**（每代 `replayFacts` 为空，索引行数为 0）。
  也就是说这组读数**不能**说明"代际台账本身的内存占用"——它测量的是"B2 代码路径存在时，既有旁路账的
  内存与 GC 形状有没有变化"。要让台账真的带负载，需要换成"每轮新增一个带重放事实的字段"的夹具，
  本文件不含该实验。
- "账的内存影响可忽略"仍然只在**本夹具规模**（4 类 / 每类单方法 / 30 轮 / 单 scope）成立，
  真实工程里的类数、方法体规模与别名链都大一到两个量级。
- 单机、单 JVM、单次运行：同口径前后对比只能在同一台机器、同一 JVM 参数下复跑得到，跨机器不复用这组绝对值。

## 9. 台账真实填充后的读数（30+30 轮，每轮都产出真实 `replayFacts`）

§8 的结论只覆盖"台账代码路径存在、但从未被填充"。本节补上那组缺失的实验：夹具换成**每轮都产生一条真实
`L1` 重放事实**的形状，让代际台账真的被写、并按窗口淘汰。

探针：`VcsGcBaselineProbe` 的 `-DvcsGcProbe.ledger=true` 模式，任务
`./gradlew :tests:vcsLedgerGcProbe -Pp05.jbr=<DCEVM JDK>`。

### 9.1 口径（与 §2 / §7 不同的部分必须显式列出）

| 项 | 取值 | 与 §2/§7 的差异 |
|:--|:--|:--|
| 夹具 | 原四个互依赖类 `D → C → B → A` **加**一对 `probe.Base` / `probe.Host`：匿名子类在实例初始化块里写父类的 `int` 字段，每轮 +1 | 多一个类 + 一个常驻实例；**因此本节绝对值不能与 §3 / §7 相减** |
| 每轮操作 | 轮换重编 `A~D` 中的一个（常量 +1），**并**重编 `Host`（初始值 +1）——同一次批量、同一个代 | 每轮多一个类、多一条事实 |
| 台账负载 | 每代 1 条 `L1` 事实；窗口 `-Dremold.vcs.changeset_window=8`，因此索引行数应按窗口收敛 | §2/§7 的事实恒为 0 条 |
| 轮数 | 预热 4 轮（不计）→ 阶段一 30 轮 → 阶段二 30 轮 | 同 §2 |
| 预算 | 阶段一 `remold.vcs.eff_bytes` 缺省（16 MiB）；阶段二 `=0` | 同 §2 |
| Retained Heap / OldGen / GC Pause | 同 §2（两次 `System.gc()` + 40 ms 静置后读；pause 采样在 settle 之前） | 同 §2 |
| 额外读数 | 台账 `accepted` 计数、索引行数 `ledgerRows`、`liveLoaderCount` | 新增 |

探针同时断言机制真的在跑（否则"曲线平"会被误读成"账很便宜"）：每轮新常量在依赖图上可见、链恰好前进 1 代、
**台账 `accepted` 计数每轮至少 +1**、**重放真的把新初值写进了那个常驻实例**。

| 台账填充 · 阶段二 · 强制淘汰 0 B | 16.29 / 16.34 / 16.36 | 16.29 / 16.34 / 16.36 | 0 / 0 / 0 | 23341 / 23341 / 23341 | 35 / 50 / 64 | 8 |

### 9.3 这组数能说明什么（已观测）

- **有真实按代留存时 Retained Heap 依然收敛**：阶段一 30 轮的带宽 `0.14 MB`（16.12～16.26，中位 16.18），
  前半段中位 `16.17` → 后半段中位 `16.21`（漂移 0.04 MB）；阶段二带宽 `0.07 MB`。两条收敛判据（整段带宽
  ≤ 1 MB、前后半段中位差 ≤ 0.5 MB）在探针里都是断言，不是事后选定的口径。
- **台账真的被填充**：`accepted` 从 5 涨到 34（阶段一）、35 到 64（阶段二），即 60 轮里每轮至少一条新事实；
  同时段 Retained Heap 没有相应爬升。
- **索引按窗口收敛而不是按轮数增长**：64 条事实之后索引行数停在 `8`（= `-Dremold.vcs.changeset_window=8`），
  证明窗口淘汰在真实链上生效——这正是"历史索引跟随 `ChangesetLog.window()`"（doc 20 §2.3）的实测形态。
- **未卸载的 loader 不拖住会话**：同一轮 GC 里，一个只被 `WeakReference` 持有的 loader 被回收（引用确实变 `null`），
  而强持有的主 loader 在同一 GC 后仍保留 8 行——这条对照说明"引用清空"不是"从来没记过"。
- **Eff 淘汰不影响事实**：阶段二 `effDropped=60`、`effBytesHeld` 三档全等于 23341（只剩当前代），台账与重放照常推进，
  因为事实存于 `Changeset.replayFacts` 而不是 Eff 字节。

### 9.4 这组数不能说明什么（推断边界）

- **不能与 §3 / §7 相减**：夹具不同（多一个类 + 一个常驻实例 + 每轮一条事实），绝对值不可跨口径比较。
  本节相对 §7 高的约 `0.3～0.5 MB` 属于**夹具差异**，不能归因于台账。
- **不能说明"台账内存上界"**：本夹具每代只有 1 条事实、1 个字段、1 个 scope；真实工程的字段数与类数大一到两个
  量级，需要换夹具重测后才能引用。
- **GC Pause 的 0 ms 仍是分辨率限制**（`getCollectionTime()` 整毫秒累加），不是"没有回收"。
- **单机单 JVM 单次运行**：三次独立运行的本节读数在 ±0.1 MB 内浮动（16.10～16.23、16.19～16.36），
  只做同口径前后对比，跨机器不复用。
- 未覆盖：多 scope、大方法体、lambda 对齐路径、`REINIT` 档事实（本夹具只产 `L1`）。
