    BOTH run/<stage>.trigger and run/run/<stage>.trigger (mkdir -p run/run) and the probe accepts both
    paths.
  * The probe now reads the server log via candidates (mm.log when cwd=run/, run/mm.log from the
    project root). Before this fix the LAYOUT-REJECT check silently read a nonexistent file and could
    never fail; the probe now asserts at baseline that it can read the log
    ("PASS stage1 probe can read the server log"), so the rejection check is demonstrably live.
  * Every javac_stage is followed by a javap marker assertion on the compiled .class (driver exits 2 on
    mismatch). One earlier iteration launched the server with stale UP-TO-DATE mixin classes and made a
    later stage look green for the wrong reason; the guard turns that into a hard driver failure.

Expected upstream-Mixin (Forge) layout semantics
------------------------------------------------
  Forge runs original SpongePowered Mixin 0.8.5/0.8.7, which MERGES two cross-mixin same-name @Unique
  fields into ONE target field. Expected applied layout at baseline and after every stage: exactly
  [uniqueA, sharedNameTag, uniqueB] -- no split into <sessionId>$<modId>$<name>$0, no duplicates, no
  LAYOUT-REJECT. The merged sharedNameTag is one storage slot, so both handlers read the SAME value;
  per-mixin value isolation is Fabric-only (sponge-mixin disambiguates).
