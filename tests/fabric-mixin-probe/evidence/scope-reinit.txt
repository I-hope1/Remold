## 3. Mutation check — RED then GREEN

Goal: prove the SELF assertions actually depend on the exact-class filter
(`instance.getClass() == canonical`), not on some unrelated signal.

Mutation applied to `core/src/remold/ref/InitFix.java` (`InitFix.scopeMatchesCanonical`), nothing else:

```diff
-		if (scope == RemoldReinit.Scope.SELF) return instance.getClass() == canonicalHost;
+		if (scope == RemoldReinit.Scope.SELF) return canonicalHost.isInstance(instance); // MUTATION: exact-class filter removed
```

(The mutated branch lives in `InitFix.scopeMatchesCanonical`; the public `InitFix.scopeMatches`
delegates to it, so both the driver path and the probe's shadow-host assertions are affected.)

Pre-mutation `sha256(InitFix.java) = af8df0d2e2425343a0975165c7591c7b3921f0e26a637d6ffef3d402131f0c82`
(file restored byte-identically afterwards; hash re-checked, and `grep -c MUTATION` = 0).

`./gradlew :tests:scopeReinitProbe` under the mutation: **exit code 1**, `passed=29, failed=6`:

```
   [FAIL] SELF: direct subclass instance must stay at its old value (1), was 7
   [FAIL] SELF: second subclass instance must stay at its old value (1), was 7
   [FAIL] baseline (before structural redefine): SELF state is p=7, a=1, b=1
   [FAIL] SELF after structural redefine: subclass instance value untouched (1), was 9
   [FAIL] SELF after structural redefine: second subclass instance value untouched (1), was 9
   [FAIL] SELF via the shadow host still excludes both subclass instances
=== SUMMARY: passed=29, failed=6 ===
```

All six failures are exactly "subclass instance was overwritten with the parent initializer", i.e.
removing the exact-class filter turns the probe red for the intended reason. After restoring the
implementation the same command is GREEN again (`passed=35, failed=0`, exit 0, run #2 above).

Negative/control coverage in the probe itself:
- `baseline (before redefine)` assertions confirm the old value was observable **before** the redefine
  (no "already 7" false positive).
- Scenario 2 (`INCLUDE_SUBCLASSES`) stays green under the mutation — it is the positive control that
  subclass instances *can* be written when the scope asks for it (so scenario 1's green is not
  "subclass instances are simply never enumerated").
- Scenario 3's added-field assertions stay green under the mutation, isolating the failure to the
  old-field exact-class filter.
